# 任务计划模型：单父树 + 依赖边

## 背景与决定

任务计划既要表达分组（阶段 → 任务 → 子任务），又要表达跨分支的先后顺序（例如「切 DNS」要等「回滚演练」和「301 验证」都完成）。纯树表达不了跨分支依赖，纯 DAG 又会让编号、拖拽和模型生成都变复杂。因此决定采用**单父树 + 依赖边**：每个节点只有一个父节点，层级用树表达；先后关系用独立的依赖边指向叶子任务，允许跨阶段，必须无环。里程碑不挂在节点上，是计划级的时间点列表。

## 被否掉的选项

- **纯树**：跨分支依赖只能写进描述或复制节点，导出后读不出真实顺序。
- **纯 DAG**：编号无法按位置稳定计算；拖拽改父节点会破坏可达性；让模型直接生成 DAG 的失败率明显更高。
- **把阶段、里程碑做成节点上的字段**：阶段与任务的语义混在一起，导出时无法统一渲染。

## 后果

- 显示编号（1、1.2、1.2.3）由树位置实时计算，不存进数据；内部 `id` 必须稳定，依赖和单节点重生成都引用 `id`。
- 「状态」不进模型：v1 只产计划，不做执行追踪。
- 周次是可选字段；缺失时导出不画周条，也不做前端自动排期。
- 单节点重生成保留原 `id` 与位置；重生成子树时新节点重新发 `id`，外部依赖指向被删除节点的情况由用户处理。
